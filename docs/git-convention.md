# Git 규칙

## 커밋 메시지

커밋 메시지는 `유형: 한글 설명` 형식으로 작성합니다.

```text
feat: 랜딩 페이지 히어로 영역 구현
fix: 폼 중복 제출 오류 수정
refactor: API 오류 처리 구조 개선
docs: 브랜치 규칙 문서화
test: URL 검증 테스트 추가
chore: 모노레포 기본 환경 설정
note: refreshToken 흐름 주석 추가
```

| 유형 | 용도 |
| --- | --- |
| `feat` | 기능 추가 |
| `fix` | 오류 수정 |
| `refactor` | 기능 변화 없는 구조 개선 |
| `docs` | 문서 변경 |
| `test` | 테스트 추가 및 수정 |
| `chore` | 의존성, 도구, 설정 변경 |
| `note` | 코드 주석 추가 및 수정 |

`style`은 별도 유형으로 사용하지 않으며 코드 의미에 영향 없는 서식 변경은 `refactor`로 처리합니다.

커밋 제목은 짧고 명확하게 작성하며 끝에 마침표를 붙이지 않습니다. 서로 관련 없는 변경은 커밋을 나눕니다.

커밋 메시지는 Husky와 Commitlint가 자동으로 검사합니다. 정의되지 않은 유형을 사용하거나 `유형: 설명` 형식을 지키지 않으면 커밋할 수 없습니다.

## 저장소 관리

- 패키지 관리자는 pnpm만 사용합니다.
- 의존성이 변경되면 `pnpm-lock.yaml`을 함께 커밋합니다.
- `.env`, 빌드 결과물, IDE 개인 설정은 커밋하지 않습니다.
- 생성된 파일을 임의로 수정하지 않습니다.
- 다른 사람의 작업을 덮어쓰거나 동의 없이 되돌리지 않습니다.
