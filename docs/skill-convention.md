# Skill Convention

프로젝트에서 반복되는 작업 방식과 실수 방지 규칙은 스킬로 관리한다. 스킬은 특정 AI 도구에 종속된 복사본을 여러 개 두지 않고, 하나의 원본을 Codex와 Claude Code가 함께 사용한다.

## 언제 스킬을 추가하는가

다음 중 하나에 해당할 때 스킬 추가를 고려한다.

- 같은 작업 절차를 여러 번 설명하고 있다.
- 저장소 고유의 판단 기준이나 반드시 지켜야 할 순서가 있다.
- 실수했을 때 Git 이력, GitHub 상태, 배포 등에 실제 영향이 생긴다.
- 반복 작업을 스크립트로 자동화하면 결과가 더 일관적이다.

일반적인 개발 상식, 한 번만 사용할 메모, 다른 문서에 이미 충분히 정의된 내용은 스킬에 중복해서 넣지 않는다.

## 저장 위치

스킬의 단일 원본은 `.agents/skills/<skill-name>`에 둔다.

```text
.agents/skills/<skill-name>/
├── SKILL.md
├── references/   # 필요한 경우에만 추가
├── scripts/      # 반복 실행이 필요한 경우에만 추가
└── assets/       # 결과물에 포함할 자료가 있는 경우에만 추가
```

Claude Code에서도 같은 스킬을 사용하도록 `.claude/skills`에는 스킬별 상대 심볼릭 링크만 둔다.

```text
.claude/skills/<skill-name> -> ../../.agents/skills/<skill-name>
```

`.claude/skills`에 `SKILL.md`를 복사하거나 별도의 내용을 작성하지 않는다. 전체 `skills` 디렉터리를 한 번에 연결하지 않고, 공유할 스킬을 개별적으로 연결한다.

## 이름과 설명

- 디렉터리와 frontmatter의 `name`은 동일하게 작성한다.
- 이름은 영문 소문자, 숫자, 하이픈만 사용한다.
- 프로젝트 전용 스킬은 `checkergie-` 접두사를 사용한다.
- `description`에는 무엇을 하는지와 언제 적용하는지를 짧게 적는다.
- 너무 넓은 설명으로 관계없는 작업에서 자동 선택되지 않게 한다.

```yaml
---
name: checkergie-example
description: Checkergie에서 특정 작업을 수행할 때 필요한 저장소 규칙을 적용한다.
---
```

## 작성 기준

- 사용자의 요청 범위와 권한을 스킬이 임의로 넓히지 않게 한다.
- 저장소에만 있는 규칙, 위험한 작업의 확인 절차, 반복해서 놓치는 판단을 우선 기록한다.
- 모든 상황을 강제하는 긴 체크리스트보다 결과에 영향을 주는 규칙만 남긴다.
- 세부 내용이 특정 상황에만 필요하면 `references`로 분리하고 `SKILL.md`에서 읽는 조건을 안내한다.
- 같은 로직을 반복 작성한다면 `scripts`로 옮기고 실제로 실행해 검증한다.
- 빈 디렉터리, 예시용 파일, 별도 README는 필요할 때만 추가한다.
- 기존 프로젝트 문서가 기준이라면 내용을 복제하지 말고 해당 문서를 읽도록 연결한다.

## 추가 절차

1. 기존 스킬과 프로젝트 문서를 확인해 역할이 겹치지 않는지 판단한다.
2. `.agents/skills/<skill-name>/SKILL.md`를 작성한다.
3. Claude Code에서도 필요하면 `.claude/skills/<skill-name>` 심볼릭 링크를 추가한다.
4. 이름, frontmatter, 링크 대상, 참조 문서와 스크립트를 검증한다.
5. 실제 작업 요청에 적용해 보고, 지나치게 넓게 선택되거나 필요한 규칙을 놓치는지 확인한다.
6. 변경 이유와 검증 결과를 해당 이슈와 PR에 기록한다.

## 검증

새 스킬이나 수정한 스킬은 최소한 다음을 확인한다.

- `SKILL.md`에 유효한 `name`과 `description`이 있다.
- 디렉터리 이름과 `name`이 일치한다.
- 문서에 미완성 표시나 예시용 placeholder가 남아 있지 않다.
- `.claude/skills` 링크가 `.agents/skills`의 실제 디렉터리를 가리킨다.
- 참조한 파일과 실행 스크립트가 존재한다.
- 기존 스킬과 역할이 불필요하게 중복되지 않는다.

Claude Code는 새 세션을 시작할 때 프로젝트 스킬을 탐색하므로, 스킬을 추가하거나 링크를 변경한 뒤에는 새 세션에서 인식 여부를 확인한다.

## 유지보수

스킬은 처음부터 완성된 규칙집으로 보지 않는다. 개발 중 실제로 반복된 문제와 팀의 합의가 생기면 좁게 보완하고, 더 이상 유효하지 않은 규칙은 제거한다. 한 도구에서만 내용을 수정하지 말고 항상 `.agents/skills`의 원본을 변경한다.
