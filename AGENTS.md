# Checkergie Web

## Repository scope

- This is a pnpm workspace containing `apps/landing`, `apps/admin`, `packages/api`, and `packages/ui`.
- The landing app is the current implemented app and the target of root CI checks.
- Admin, API, and UI are intentionally scaffolded for team members to implement.
- Keep environment files local. Do not commit secrets or `.env*` files.

## Runtime and package manager

- Use Node.js `24.14.0` from `.nvmrc`.
- Use pnpm `11.9.0`; do not use npm or yarn.
- Keep `pnpm-lock.yaml` in sync with dependency changes.
- `pnpm-workspace.yaml` explicitly allows only the required `unrs-resolver` install build.

## Commands

```bash
pnpm install
pnpm dev          # landing: http://localhost:3000
pnpm dev:admin    # admin: http://localhost:3001 (once implemented)
pnpm storybook    # UI catalog: http://localhost:6006
pnpm check:ui     # UI lint + typecheck + Storybook build
pnpm check        # landing lint + typecheck + production build
```

Run `pnpm check` before opening a pull request. Use package-level scripts when
working inside a package; do not broaden root checks until the scaffolded
packages have real implementations.

## Next.js conventions

- Use the App Router under `src/app` and React Server Components by default.
- Use `next/navigation` in App Router code; do not introduce Pages Router APIs.
- Use the Metadata API instead of `next/head`.
- In Next.js 16, treat `cookies()`, `headers()`, `params`, and `searchParams` as async APIs.
- Add `"use client"` only to components that need browser state, effects, or event handlers.

## UI design system

- Build shared UI in `packages/ui`; do not place design-system components in `apps/landing` or `apps/admin`.
- Follow Atomic Design: foundations, atoms, molecules, then organisms. Compose upward instead of duplicating lower-level behavior.
- Use Tailwind CSS 4 and the `cg` semantic tokens in `packages/ui/src/styles/theme.css`. Prefer tokens over raw colors, spacing, radii, shadows, typography, z-index, and motion values.
- Pretendard is the product font. New typography should use the semantic `text-cg-*` utilities.
- Every reusable component needs focused Storybook stories for its meaningful states. Keep foundation stories reference-like, not landing-page-like.
- Interactive controls need visible focus, correct pointer/disabled/loading cursors, keyboard behavior, accessible names, and reduced-motion handling.
- Use `docs/design-system.md` for package conventions and `.agents/skills/checkergie-design-system` for the implementation workflow.

## Changes and collaboration

- Prefer small, focused changes and preserve unrelated work in the working tree.
- Treat `docs/git-convention.md` and `docs/branch-convention.md` as the source of truth for Git collaboration.
- Branch from the latest `develop` using `feature/short-english-name` for features or the matching documented task type, then open a pull request back to `develop`.
- Do not include issue numbers in branch names. Use the branch name as the pull request title and link the issue in the body with `Closes #N`.
- Use `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, or `note` commit types with a concise Korean subject. Do not use `style`; classify those changes as `refactor`.
- Keep each pull request focused on one purpose and obtain review approval before merging. No specific merge method is required.
- Do not commit directly to `main` or `develop`; run the relevant checks before merging.
